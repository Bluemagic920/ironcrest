# Attendance records implementation

Owner dashboard: index.html loads attendance-records.js. It adds a read-only shift list, UTC date window (31 days maximum), employee/worksite filters, closed hours clipped to the selected window, open-shift and exception visibility, and CSV of displayed shifts. Open shifts do not add unapproved hours. Invalid/future/reversed timestamps need review. Totals cover displayed records, never an inferred payroll total. Lists cap at 200 records and disclose truncation. Exports neutralize spreadsheet formulas.

Backend extension: worker/attendance-records.mjs exports createAttendanceRecordsRoute. Integrate it into the CURRENT existing ironcrest-invitations-api Worker before its unmatched-route handler. Construct the route once, then call it inside fetch(request,env); when its result is non-null, return that Response. Do not replace the existing Worker or its routes with this module. Current deployed Worker source must be retrieved and reviewed before integration; it is not available in this repository. No production integration is claimed.

The handler only serves GET/OPTIONS /api/attendance/records. Required bindings: existing SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY and encrypted SUPABASE_SERVICE_ROLE_KEY; URL is restricted to the current shared project. ENABLE_ATTENDANCE_REPORTS_READONLY is false/unset by default. This switch is separate from all attendance write switches; never enable a write switch for this feature. Reuse existing encrypted bindings in the existing Worker, do not copy keys into source/files/chat or create a separate privileged Worker without review.

Authorization verifies the Supabase user and confirmed email, exactly one active OWNER membership, matching organization creator, and existing Business entitlement. All queries derive organization from that verified membership; a caller-supplied organization is rejected. Modern server keys use apikey only, user JWTs remain separate. The existing STABLE service-only Business RPC is invoked by POST for a read-only entitlement query; it performs no attendance mutation. Anonymous/browser direct-table access remains denied. No migrations, grants, RLS policy changes, time-record changes or payroll sends are needed.

Tables/columns and present service-only access were checked through read-only metadata queries. No attendance/customer rows were retrieved during development. Backend tests use fake providers, frontend tests run actual production scripts in a local DOM fixture. Browser preview with invented records verified 8.50 closed hours, one open shift, one pending exception, and employee filtering to zero closed hours for the open-only employee. ## Employee self-service and hours validation

Employee portal now mounts the same report at /api/attendance/my-records. The server derives the employee ID from the verified Supabase user, requires exactly one active employee membership and Business entitlement, and adds BOTH organization and employee-user filters to attendance and exception queries. Caller-supplied employee/organization query parameters are rejected. Profile labels are restricted to the current employee; worksite labels are restricted to referenced worksite IDs. Provider rows that mismatch the current employee are rejected. Browser employee mode requires selfScoped=true in the report response. No table grants or policies were changed.

Timestamp parsing now requires explicit time zones and valid dates. Overlapping shifts for the same employee are flagged and excluded from closed-hour totals, even when one overlap is hidden by a worksite filter. Open shifts still appear as open but never add unapproved hours. This is reporting only; it is not an overtime/payroll calculation. Session-expired messages are distinguished from a disabled reporting service. No ADP development or signup is underway; Chris deferred ADP.

31 tests pass including employee isolation, foreign-row rejection, self-scoped frontend, timezone/calendar validation, overlapping/adjacent shifts and expired authentication. Five inline scripts pass syntax validation. The employee extension and current hours changes were tested with fixtures, not deployed against live accounts. Production integration of both routes remains pending retrieval of the current existing Worker.
