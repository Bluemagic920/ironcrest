# Employee profiles

This update extends the existing owner Employee Directory rather than adding a duplicate owner editor. It fixes the previous mismatch where the browser sent a contact email but the original Worker rejected that field.

Owners manage employee names, job titles, employment status, phone numbers and contact emails. Employees use **My Profile** to see their own details and update only their own phone/contact email. Contact email is a profile field; it never changes `auth.users`, passwords or sign-in email. Employment status is a personnel label and does not change membership access, assignments, scheduled shifts or attendance. A missing profile must be completed by the owner before employee contact edits become available.

The employee endpoint is GET/PATCH `/api/employee/profile`; it accepts no scope parameters or employee identifiers. The Worker derives the current user, sole active employee membership and organization from verified authentication and database membership. Owner updates keep PATCH `/api/employees/profile`, adding an expected revision. Both require current Business entitlement and the existing rate limiter. Contact writes reject name/job/status/membership/role/organization fields from employees. Server credentials never enter the browser and provider redirects are rejected.

The release gate is `ENABLE_EMPLOYEE_PROFILES=true`. Until enabled, the new employee endpoint is closed and the existing owner profile route remains in place. Once enabled, cached old owner forms without a revision receive a reload instruction instead of overwriting a newer profile. The existing owner directory includes contact email and revision only when the gate is enabled.

The reviewed hosted migration snapshot is `docs/employee-profile-schema.sql` (`ironcrest_employee_contact_profiles`). It adds a revision counter to the existing table, with a before-update trigger that advances the revision for every writer. Existing profile RLS, policies and grants stay unchanged. The service-only security-invoker update function rechecks owner or self membership and Business access, serializes changes on the target membership/profile, verifies revision, and changes only allowed fields. A private RLS edit journal records actor, target, action, revision and timestamp, without copying old/new phone or email values. Profile save and journal insertion commit together. No grants to ordinary clients are added.

The browser clears contact data on account changes, fences late responses, and prevents an uncertain save from being blindly retried before reload. Opening My Profile scrolls it into view, matching the existing Worksites/Scheduling navigation. Owners use the current directory editor; conflict failures require reloading the directory.

Validation: actual Worker integration and DOM/network fixture tests; isolated PostgreSQL tests covering owner/employee competing edits, protected employment fields, revocation, revision changes from other writers, unchanged sign-in email, and audit failure rollback. A hosted rollback-only transaction verified owner save, employee contact save and stale/protected-field rejection without retaining test profile edits or journal rows. Browser preview used invented employee data and verified contact saving. Release requires approval for new employee access to their own contact records, then live owner and authentication boundary checks. Company announcements and ADP are outside this change.
